# Backup/restore drill — 2026-07-24 (production code path)

## Что доказывает и чего не доказывает

**Доказывает:** инструмент и процедура резервного копирования и восстановления
работают — тот самый код, что гоняет прод (`apps/api/src/ops/backup-to-s3.ts`,
крон `alistore-backup-prod`, `render.yaml`), делает читаемый дамп, кладёт его в
S3-совместимое хранилище, и объект оттуда восстанавливается в рабочую БД, которая
проходит проверку целостности.

**Не доказывает:** что в продовом бакете `alistore-backups-prod` (Cloudflare R2)
сейчас лежат восстановимые объекты. Это требует ключей R2 и остаётся действием
владельца (`docs/OWNER-LAUNCH-CHECKLIST.md`). Отдельно от кода бэкапа — см. `§4`
`docs/MASTER-PLAN.md`.

Предыдущий drill (18.07, `infra/RUNBOOK.md`) гонял `infra/backup.sh` — **локальный
dump другим инструментом**. Этот — впервые продовый путь `ops/backup-to-s3.ts`.

## Стенд

- Хранилище: локальный MinIO из `infra/docker-compose.yml` (S3-совместимый,
  `:9000`), бакет `alistore-backups-drill`. Тот же `S3Client`, gzip, раскладка
  ключей `postgres/…`, что у прода.
- Источник: изолированная БД с реальными данными (продажа, платёж, проводки) —
  27 счетов, 21 проводка, 9 событий леджера.
- Сборка: `npm run api:build`; запуск `node apps/api/dist/ops/backup-to-s3.js`.

## Негативные проверки затвердений (защита от «сломанный бэкап выглядит рабочим»)

| Проверка | Доказательство |
|---|---|
| Целостность | усечённый до 1/3 дамп `pg_restore --list` отбивает (exit 1, EOF); целый — 1187 строк оглавления. Джоба падает до загрузки. |
| Маркер провала | живая БД + несуществующий бакет → джоба падает, пишет `ops.backup.last_failure`, прежний `ops.backup.last_success` сохранён |

| libpq-URL | `?schema=public&connection_limit=5` вычищается, `sslmode` сохраняется (юнит `apps/api/test/backup-to-s3.spec.ts`) |

## Дефекты, найденные drill'ом и починенные (коммит `d543b9bc`)

1. Отсутствовала проверка целостности — усечённый дамп помечался успехом.
2. `?schema=` роняет `pg_dump` (прод спасён только тем, что Render даёт голую строку).
3. Безусловный SSE-S3 не поддержан Cloudflare R2; MinIO отвергает.
4. Ротации не было вовсе — объекты копились вечно.
5. Дамп дважды буферизовался в памяти с потолком 1 ГиБ.

## Открытые пробелы (в BACKLOG, требуют staging/владельца)

- Восстановление именно из прод-бакета R2 не проверялось (ключи владельца).
